# DevOps-проект: автоматический деплой веб-приложения

Учебный pet-проект, в котором я на практике собрал полный цикл CI/CD —
от кода до работающего сайта с SSL на реальном VPS, без единого ручного
шага при деплое.

## Что делает проект

При каждом пуше в ветку `main`:

1. GitHub Actions настраивает сервер через Ansible (Docker, Nginx, SSL-сертификат).
2. Собирает Docker-образ с сайтом.
3. Копирует образ на VPS по SSH.
4. Перезапускает контейнер с новой версией.

Результат — сайт обновляется автоматически, без захода на сервер руками.

---

## Стек

- **Docker** — упаковка приложения в контейнер
- **Nginx** — реверс-прокси + раздача статики
- **Ansible** — настройка сервера (Infrastructure as Code)
- **GitHub Actions** — CI/CD пайплайн
- **Let's Encrypt / certbot** — автоматический выпуск SSL
- **Linux (Ubuntu VPS)**

## Как это работает

### 1. Настройка сервера (Ansible)

Ansible приводит сервер в нужное состояние:

- ставит Docker
- ставит и настраивает Nginx
- поднимает реверс-прокси на нужный порт
- выпускает и обновляет SSL-сертификат через certbot

Запуск вручную:

```bash
cd ansible
ansible-playbook -i inventory.ini playbook.yml
```

### 2. Контейнеризация приложения

Сайт — статичный HTML, упакованный в лёгкий образ на базе `nginx:alpine`:

```dockerfile
FROM nginx:alpine
COPY app /usr/share/nginx/html
```

### 3. CI/CD (GitHub Actions)

При пуше в `main`:

1. Провижининг сервера через Ansible (если что-то изменилось в инфраструктуре).
2. Сборка Docker-образа.
3. Сохранение образа в архив (`.tar`).
4. Копирование архива на сервер по SCP.
5. По SSH: загрузка образа, остановка старого контейнера, запуск нового.

## Что было сложного на практике

Не всё заработало с первого раза, и часть пайплайна я отлаживал по логам
реальных прогонов CI — что было полезнее любого туториала:

- Ansible молча пропускал все задачи (`hosts: vps` не матчился с
  инвентарём, который передавался в CI через `-i`) — исправил на `hosts: all`.
- SSH падал с ошибкой проверки host key на новом раннере — настроил
  `~/.ssh/config` со `StrictHostKeyChecking no` для CI.
- Столкнулся с багом в свежей версии `ansible-core` (падение при сборе
  фактов) — зафиксировал версию пакета.
- Sudo на сервере требовал пароль при выполнении задач с `become: true` —
  настроил passwordless sudo для деплой-пользователя.

## Известные ограничения

- Образ передаётся на сервер архивом (`.tar`) через SCP, а не через Docker Registry.
- Нет zero-downtime деплоя — контейнер на секунду выключается при обновлении.
- Нет мониторинга и алертинга.

## Что хочу добавить дальше

- Перейти на Docker Registry (Docker Hub / GHCR) вместо передачи `.tar`.
- Zero-downtime деплой.

- Terraform для управления самим сервером, а не только его содержимым.
